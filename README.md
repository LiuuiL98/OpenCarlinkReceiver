# OpenCarlinkReceiver

用于研究 ICCOA Carlink 兼容性的实验性基础安卓主机接收。

> **当前状态：** 仅为测试原型。本项目尚未实现 ICCOA Carlink 协议，也不保证与任何品牌的手机兼容。真正的协议支持需要经过验证的规范或授权的 SDK 加上实际设备测试。

## 目标

- 广泛的安卓兼容性，目标为 **Android 4.4 (API 19)+**。
- 以 Java 为主的轻量级安卓应用。
- USB 设备诊断以及 Wi-Fi 功能/状态诊断。
- MediaCodec 功能检测和 SurfaceView 渲染基础。
- 将传输、协议、渲染和诊断模块分开，以便后续可以添加已验证的 Carlink 支持。
- GitHub Actions 构建工作流。

## Build

在 Android Studio 中打开这个仓库，或者用 Gradle 8.9 和 JDK 17 构建：

```bash
gradle assembleDebug
```

APK 文件生成在 `app/build/outputs/apk/debug/app-debug.apk`.

## 首版原型功能

- 设备/API/ABI 概览。
- USB 主机功能和已连接的 USB 设备列表。
- Wi-Fi 状态和 Wi-Fi Direct 功能可用性。
- Android MediaCodec 可用的 H.264 解码器。
- 一个基本的接收屏幕和诊断日志。

## 重要的协议说明

- USB 对 Android 可见并不意味着建立了 ICCOA 会话。
- Wi-Fi 连接并不意味着支持 Carlink。
- 不要随意创造协议数据包格式或握手信息。
- 协议适配器只是一个占位符，直到相关规范/SDK 和法律整合条件得到验证。
- Android 4.4 支持描述的是应用的基础平台，而不是保证与每个 SDK 或手机兼容。

## 发展路线

1. 构建并安装诊断原型。
2. 收集来自真实主机和支持的手机的诊断数据。
3. 确认 ICCOA Carlink SDK 的可用性、API 级别支持、本地 ABI 要求以及集成/审批条款。
4. 为一个手机型号实现并测试真实会话。
5. 添加视频、音频、触控/控制通道，处理重连，然后扩大设备覆盖范围。
6. 只有在基本投屏功能可用后，再研究桌面融合功能。

## USB/AOA 诊断会话（0.2.2）

本分支增加了用于排查三星手机 ICCOA Carlink 连接的阶段化诊断功能：

1. **前置检查**：用户手动确认手机端已开启 USB 调试并保持解锁亮屏。运行在车机端的应用无法自动读取另一台手机的 USB 调试状态，因此此处属于人工确认，不是系统检测。
2. **USB 发现与权限**：记录 USB 设备 VID/PID、接口数量、本应用的 USB 权限状态及权限回调。
3. **AOA 协商**：记录请求 51 返回的 AOA 版本、请求 52 各身份字段发送是否成功及 UTF-8 字节长度、请求 53 的返回值。
4. **Bulk IN 只读测试**：记录读取次数、字节数、超时/错误结果；诊断导出会省略原始 HEX 数据样本。
5. **本地日志与导出**：阶段日志保存于应用私有 SharedPreferences，提供系统分享菜单导出和手动清除。日志受长度上限约束。

### 建议测试顺序

- 在发送端手机开启 USB 调试，解锁并保持亮屏。
- 在车机端打开应用，勾选两项前置条件并开始新的诊断会话。
- 先点击“申请 USB 权限并测试打开连接”，确认基础 USB 访问。
- 记录结果后，再点击“发送 ICCOA AOA 身份并切换手机模式”。此操作会发送标准 AOA 请求 51/52/53，并可能造成手机 USB 重新枚举或中断 ADB。
- 重新连接后刷新 USB 设备列表，确认是否出现预期的 AOA 配件 VID/PID。
- 通过“导出/分享脱敏诊断日志”分享结果。不要在公开日志中附上真实配对码、完整六段 AOA 前导信息或未脱敏的 USB 序列号。

**诊断结果限制：** 请求 53 被 USB 层接受只表示切换请求被接受，不代表手机已完成重新枚举，也不代表 ICCOA 配对、认证或投屏会话成功。当前版本仍未实现完整 ICCOA 业务协议。
